What Go is

Go was built at Google by Robert Griesemer, Rob Pike, and Ken Thompson, and it's open source under a BSD-style license (roughly: use it freely, no warranty). The headline features:

  • Compiled: source turns into a native binary, not bytecode that gets interpreted.
  • Statically typed: a variable always refers to the same type of value.
  • Structurally typed: two types are equivalent if their structure matches, not because they share a name.
  • Memory safe: no buffer overflows, no unsafe pointer arithmetic.
  • Garbage collected: you don't manually free memory.
  • Built around concurrency: this is one of Go's biggest selling points.

The overall feel: Go wants there to be exactly one right way to do something, and the compiler enforces it. Things Python only warns about (an unused variable, an unused import) are flat-out compile errors in Go.

Style is compiler-enforced (and gofmt)

A lot of languages have "flame wars" about the right way to format code, indent, name things, and so on. Go mostly sidesteps this by making the compiler itself reject non-idiomatic patterns rather than just warning about them: an unused import or an unused local variable is a hard compile error, not a lint suggestion.

On top of that, Go ships with gofmt, a tool that automatically rewrites your source into the one canonical formatting style (spacing, brace placement, alignment). Most editors run it on save, so arguments about tabs vs. spaces or brace placement mostly don't happen in Go. 

gofmt -w main.go   // rewrite main.go in place to standard style

Basic types

Go splits types into basic/predefined types and everything else (structs, custom types, etc). The basic types are booleans, strings, and a family of number types: 

bool
string

int8    int16   int32   int64   int
uint8   uint16  uint32  uint64  uint
byte    // alias for uint8
rune    // alias for int32, holds one Unicode code point

float32 float64

Unless you have a specific reason to size things down (network protocols, matching a C struct layout, etc.), you'll mostly just use int, float64, string, and bool.

Literals

A literal is a value typed directly into the source code, like 42 or "hello". Go has default types for each kind of literal:

  • Integer literals default to int, base 10. Prefix with 0x for hex, 0b for binary, 0o for octal.
  • Floating point literals default to float64.

Interpreted vs. raw string literals

Double-quoted strings are "interpreted": escape sequences like \t and \n get replaced with the actual tab/newline character. Backtick strings are "raw," and nothing gets replaced, so a backslash-t is genuinely two characters, not a tab. 

a := "this \t has a tab \n and a newline"
// interpreted: the \t and \n become real characters

b := `this \t has a tab \n and a newline`
// raw: the backslashes stay literal, nothing is replaced

Runes

A single character (technically, a Unicode code point) is called a rune in Go. rune is just an alias for int32, since a Unicode code point fits in 32 bits. 

var r rune = 'A'
fmt.Println(r)        // 65 (the numeric code point)
fmt.Println(string(r)) // "A"

Type conversion

Python auto-promotes numbers as needed. Java will auto-widen a less precise type to a more precise one when it's on the right side of an assignment (an int can silently become a float, but not the reverse). Go does neither. it wants everything explicit. Converting a value is done by calling the target type like a function: 

var x float64 = 34.5
var y float32 = 13.2

z := x + float64(y) // must convert y explicitly, or this won't compile

Literals are the one exception: they're untyped until assigned, so they can be coerced into a more precise type automatically. 

var x float64 = 3.5
y := x * 10 // fine, 10 gets treated as a float64 literal here

var z int = 10.4     // compile error, this loses precision
var a int = "a string" // compile error, wrong type entirely

Variables

There are two main ways to create a variable in Go:

// short form, := infers the type, only works inside a function
x, y := 12, 20

// var form, works at package level or inside a function
var x, y int = 12, 20

With :=, at least one name on the left has to be new, and the others can be existing variables getting a new value. With var, every name must be new, and all of them must be the same type.

If you declare a variable without a value, it gets that type's zero value automatically: 0 for numbers, "" for strings, false for booleans, nil for pointers/slices/maps. 

var count int    // count is 0
var name string  // name is ""

Go also treats an unused local variable as a compile error, not a warning, and the same goes for an unused import. That rule is specifically about local variables, though: an unused package-level variable (one declared outside any function) is allowed.

Constants

Use const for an immutable, compile-time value. Go's naming convention for constants is the same as for regular variables (not ALL_CAPS like Java/C++), because in Go, capitalization actually controls export visibility rather than signaling "this is a constant." 

const x int32 = 50

const (
    Left  = true
    Right = false
)

Arrays

An array in Go is a fixed-size, sequential block of memory holding elements of the same type. The size is actually part of the type in fact, [4]int and [10]int are two different types, not the same type with a different length. That makes arrays fast, but restrictive: a function that takes a [4]int can't also accept a [10]int. 

var directions = [4]int{1, 2, 3, 4}
directions[1] = 10 // still only ever 4 slots

var zeroed [4]int // all four elements start at the zero value

Because of that restriction, almost nobody uses raw arrays directly in Go. Slices (below) are what people actually reach for.

Slices

A slice is a resizable view into an underlying array, the closest thing Go has to Python's list or Java's ArrayList. Every slice tracks three things: a pointer to an element in an array, a length (how many elements are in the slice), and a capacity (how far the underlying array goes before it needs to be reallocated). 

var empty []int      // zero value of a slice is nil, len(empty) == 0

names := make([]string, 5, 10)
// type string, length 5, capacity 10
// if you omit the capacity, it defaults to match the length

Adding to a slice

Use append, which returns a (possibly new) slice:

names = append(names, "Santore")               // one value
names = append(names, "Jung", "Black", "Sattar") // several values

names2 := []string{"Li", "Kim"}
names = append(names, names2...) // spread another slice into append

Slicing syntax

Go also supports Python-style slicing with start:end inside the brackets. This creates a new slice header that still points at the same underlying data, so changing one can affect the other. 

names := []string{"Santore", "Jung", "Black", "Sattar", "Li"}
firstThree := names[:3] // Santore, Jung, Black
lastTwo := names[3:]    // Sattar, Li

Slices as parameters

Slices are passed by value like everything else in Go, but since the "value" is really just the pointer/length/capacity triple, you can still mutate the underlying array's contents through a slice parameter. You just can't reassign what the caller's slice variable points to.

Console input and output

Writing to the console uses fmt.Println or fmt.Print, with values separated by commas: 

fmt.Println("Score:", score, "Lives:", lives)

Reading input takes two steps: wrap stdin in a buffered reader, then call one of its read methods.

reader := bufio.NewReader(os.Stdin)
line, err := reader.ReadString('\n')
// reads until the user presses Enter

Maps

Go's maps are hash tables, working much like a Python dictionary. Keys have to be a comparable type (anything you could use == on); values can be any type. 

wages := make(map[string]float32)

// or build one with a literal
wages := map[string]float32{
    "Ed":  450.17,
    "Ann": 375.99,
}

Looking up a key that isn't in the map doesn't error. It just returns the zero value for the value type. If you need to tell "the value really is zero" apart from "the key wasn't there," use the comma-ok form: 

earnings, ok := wages["John"]
// earnings == 0.0, ok == false, since "John" isn't a key

Structs

A struct is a collection of named, typed fields, essentially the same idea as a C struct or a plain data class. 

type Player struct {
    Name         string
    Health       int
    JumpDistance int
}

var p1 Player          // zero value for every field
p1.JumpDistance = 3    // access fields like you would in C

Struct literals

p2 := Player{"Mario", 1, 2}                 // positional
p3 := Player{Name: "Luigi", Health: 1}      // by field name, JumpDistance stays 0

Exporting: capitalization matters

Unlike naming conventions in most languages, capitalization in Go is functional: a capitalized struct or field name is exported (visible outside its package); a lowercase one is package-private. Player above is exported, but a lowercase field like jumpDistance wouldn't be reachable from another package.

Nesting and embedding

A struct can hold another struct as a named field (no recursive definitions allowed, though. You'd need a pointer for that): 

type SaveGame struct {
    P    Player
    Size int
}

save := SaveGame{P: p1, Size: 128}
fmt.Println(save.P.Name) // reach through the nested struct

Go also supports embedding: including a struct type with no field name promotes its fields up to the outer struct, so you can skip the intermediate name: 

type SaveGame struct {
    Player // embedded, no field name
    Size   int
}

save := SaveGame{Player: p1, Size: 128}
fmt.Println(save.Name) // Player's fields are promoted - no save.Player.Name needed

How a statement ends

A quick language comparison worth having straight for a quiz:

  • Java (and C/C++/C#): every statement ends with a semicolon ;.
  • Python: a statement ends at the end of the line, no punctuation needed.
  • Go: also ends at the end of the line, and semicolons are "optional" in the sense that you almost never type one yourself. Behind the scenes, the compiler scans each line and automatically inserts a semicolon after it where one is needed, so the result behaves like Java under the hood while reading like Python on the page. gofmt will strip out any semicolons you do type by hand.

if / else

No parentheses around the condition, but the braces are mandatory even for a one-line body. 

if num := 9; num < 0 {
    fmt.Println(num, "is negative")
} else if num < 10 {
    fmt.Println(num, "has 1 digit")
} else {
    fmt.Println(num, "has multiple digits")
}

That num := 9; part is an init statement. A variable declared there is scoped to the whole if/else if/else chain, available in every branch.

for (and no while)

Go collapses definite and indefinite repetition into a single keyword: for. There's no separate while.

Classic three-part for

for counter := 10; counter > 0; counter-- {
    fmt.Println(counter)
}
fmt.Println("blastoff")

While-style (condition only)

Drop the init and post parts and you get what other languages call a while loop:

sum := 1
for sum < 1000 {
    sum += sum
}
fmt.Println(sum)

The forever loop

for {
    // runs until something inside calls break
}

break and continue

break exits the innermost for, switch, or select. continue skips to the next iteration without finishing the current one. Both work the same as in C-family languages.

for-range

The modern way to iterate over a collection, similar to Python's for x in items or Java's enhanced for loop: 

names := []string{"Santore", "Jung", "Black"}
for i, name := range names {
    fmt.Println(i, name)
}
// first variable is the index (or key, for a map)
// second variable is the value

Things that trip people up

  • Iterating over a map returns entries in a different order every run, on purpose. It's a defense against hash-flooding attacks where someone crafts keys that all land in the same bucket.
  • The values you get from for-range are copies of the location and value in the collection. If you mutate the loop variable, the original collection doesn't change. you have to index back into it to update the source.
  • Iterating over a string yields runes, not bytes, so multi-byte characters won't throw off your indexing the way a byte-by-byte loop would.

The blank identifier

An unused local variable is a compile error in Go, so if you only want the value and not the index (or vice versa), use _ to explicitly throw the other one away: 

for _, name := range names {
    fmt.Println(name) // don't care about the index here
}

Never use _ to discard an error return value. That silently swallows exactly the thing you're supposed to be checking.

switch

Works like a C/Java switch, but simpler: no fall-through by default, so no break needed at the end of each case. Any comparable type can be a switch value. 

switch answer {
case "yes":
    fmt.Println("You have answered correctly")
case "no":
    fmt.Println("Consider being a team player")
case "maybe":
    fmt.Println("I'll ask again after lunch")
}

Blank switch

Leave out the value after switch and each case becomes its own boolean condition instead of an equality check, which is handy for ranges or substring checks: 

switch {
case strings.Contains(answer, "yes"):
    fmt.Println("Matched a yes-ish answer")
case strings.Contains(answer, "no"):
    fmt.Println("Matched a no-ish answer")
default:
    fmt.Println("Not sure")
}

Functions

Declared with func. The return type comes after the parameter list (unlike Java/C++, but like Python's -> style). The opening brace has to be on the same line as the signature. Go doesn't let you argue about that one. 

func add(x int, y int) int {
    return x + y
}

A function that has no return type doesn't need return at all, but you can still use a bare return with no value to exit early, partway through the function body: 

func printPositive(n int) {
    if n <= 0 {
        fmt.Println("not positive, skipping")
        return // exits early, no value needed
    }
    fmt.Println(n)
}

Multiple return values

Go leans on multi-value returns heavily, especially for the "result, error" pattern used throughout the standard library: 

func divide(a, b float64) (float64, error) {
    if b == 0 {
        return 0, errors.New("division by zero")
    }
    return a / b, nil
}

result, err := divide(10, 2)
if err != nil {
    log.Fatal(err)
}

The standard library leans on this constantly. net/http's Get function, for example, has this exact shape: 

func Get(url string) (resp *Response, err error)

resp, err := http.Get("https://example.com")
if err != nil {
    log.Fatal(err)
}
defer resp.Body.Close()

Named return values ("naked return")

You can name the return values in the signature; they start at their zero value and you can just return with no arguments once they're set. Considered a bit old-fashioned/frowned on by more recent Go style, but you'll still see it: 

func factorial(n int) (answer int, err error) {
    if n < 0 {
        err = errors.New("can't take factorial of a negative number")
        return
    }
    answer = 1
    for ; n > 0; n-- {
        answer *= n
    }
    return // "naked" return - sends back answer and err as they stand
}

Functions as values

Functions are first-class values in Go, same as in Python or Rust (unlike Java or C/C++ before lambdas were bolted on). You can assign a function to a variable, pass it as a parameter, or return it from another function.

Closures

A function defined inside another function can capture variables from the enclosing scope:

func main() {
    factor := 5
    multiply := func(x, y int) int {
        return factor * (x + y)
    }
    fmt.Println(multiply(1, 1)) // 10
}

Anonymous functions

A function used as a value doesn't need a name at all:

func counter() func() int {
    count := 0
    return func() int {
        count++
        return count
    }
}

next := counter()
fmt.Println(next()) // 1
fmt.Println(next()) // 2

Functions as parameters

Standard library functions like strings.Map take a function as an argument:

shift := func(r rune) rune {
    if r >= 'a' && r <= 'z' {
        return 'a' + (r-'a'+1)%26
    }
    return r
}
fmt.Println(strings.Map(shift, "abcxyz")) // "bcdyza"

Functions aren't comparable with == (so they can't be used as map keys), but they can always be compared to nil, which is a function's zero value.

Function types have to match exactly

Go is strongly typed even for functions: a variable's function type is defined by its parameter types and return type, and a reassignment has to match precisely, not just "close enough." 

var op func(int64, int64) int64
op = func(x, y int64) int64 {
    return x + y
} // compiles: int64 params and return match exactly

op = func(x, y int) int {
    return x + y
} // does NOT compile: int != int64, even though the logic is identical

defer

defer schedules a function call to run right before the current function returns, whether it returns normally, falls off the end, or panics. It's mainly used to guarantee cleanup (closing a file, unlocking a mutex) happens no matter how the function exits, without repeating the cleanup call at every return point. 

func readConfig(path string) error {
    f, err := os.Open(path)
    if err != nil {
        return err
    }
    defer f.Close() // runs no matter which return below fires

    // ... use f ...
    return nil
}

Multiple defer calls in one function run in last-in-first-out order, like a stack. Watch out for defer inside a loop, though. The deferred calls all stack up and don't actually run until the whole function returns, not at the end of each loop iteration, which can hold resources open far longer than intended. 

func readAll(paths []string) {
    for _, p := range paths {
        f, err := os.Open(p)
        if err != nil {
            continue
        }
        defer f.Close() // BAD: none of these run until readAll itself returns,
        // so every file in the loop stays open the whole time, not just
        // while it's being used
    }
}

The fix is usually to move the loop body into its own function (or an anonymous function called immediately), so each defer fires at the end of that smaller scope instead of piling up until the very end.

Errors

Go doesn't have exceptions. Instead, a function that can fail returns an error as its last return value, by convention. Since Go won't let you leave a declared variable unused, you're effectively forced to at least look at the error: 

resp, err := http.Get("https://example.com")
if err != nil {
    log.Fatal(err)
}
defer resp.Body.Close()

Don't use _ to throw away an error return value. It'll compile, but it means a real failure just vanishes silently instead of being handled, which is considered a serious anti-pattern in Go.

Reading a text file

func readLines(path string) ([]string, error) {
    contents, err := os.ReadFile(path)
    if err != nil {
        return nil, err
    }
    text := string(contents)
    return strings.Split(text, "\n"), nil
}

This returns one string per line, similar to Python's readlines().

Utility: stripping punctuation from a string

A handy one-off shown in the slideshow, sourced from gosamples.dev, for cleaning up text before processing it (useful before splitting a file into words, for example). It uses a compiled regular expression to strip anything that isn't a letter, digit, or space. 

var nonAlphanumeric = regexp.MustCompile(`[^a-zA-Z0-9 ]+`)

func cleanString(s string) string {
    return nonAlphanumeric.ReplaceAllString(s, "")
}

cleanString("Hello, world!!") // "Hello world"

First in-class project: reading a slice of structs

The first project of the semester: a loop that repeatedly asks for a class name, instructor, and credit count, packs each answer into a Classes struct, and appends it to a slice. It stops as soon as the user's answer to "add another class?" isn't "yes", then prints the whole slice with a numbered for-range loop.

It also shows two things worth noticing: strings.TrimSpace to strip the trailing newline that ReadString('\n') leaves on the input, and strconv.Atoi to turn the typed-in credit count from a string into an int. 

package main

import (
	"bufio"
	"fmt"
	"os"
	"strconv"
	"strings"
)

type Classes struct {
	className       string
	instructorName  string
	numberOfCredits int
}

func main() {
	classes := make([]Classes, 0)
	reader2 := bufio.NewReader(os.Stdin)
	for {
		nextClass := Classes{}
		fmt.Println("Please enter a name for the class")
		className, err := reader2.ReadString('\n')
		println(err)
		nextClass.className = strings.TrimSpace(className)
		fmt.Println("Please enter a name for the instructor")
		instructors, err := reader2.ReadString('\n')
		nextClass.instructorName = strings.TrimSpace(instructors)
		fmt.Println("Please enter a number for the credit number")
		number, err := reader2.ReadString('\n')
		number = strings.TrimSpace(number)
		numberInt, err := strconv.Atoi(number) //trim newline
		nextClass.numberOfCredits = numberInt
		classes = append(classes, nextClass)
		fmt.Println("Do you want to add another class?(yes/no)")
		answer, err := reader2.ReadString('\n')
		answer = strings.TrimSpace(answer)
		if answer != "yes" {
			break
		}
	}
	for i, class := range classes {
		fmt.Printf("%d. %s, instructor: %s, credits: %d\n", i+1, class.className, class.instructorName, class.numberOfCredits)
	}
}

In-class example: print every other line

A small program that reads a text file and prints only the odd-indexed lines (every other line starting from the second one). It uses os.ReadFile plus strings.Split to get the file into a slice of lines, then a for-range loop with the modulo operator to pick out every other entry. 

package main

import (
	"fmt"
	"os"
	"strings"
)

func main() {
	allLines := getFile()
	for i, line := range allLines {
		if i%2 == 1 {
			fmt.Println(line)
		}
	}
}

func getFile() []string {
	contents, err := os.ReadFile("sillyRec")
	if err != nil {
		fmt.Println("File reading error", err)
		return nil
	}
	bigString := string(contents)
	allLines := strings.Split(bigString, "\n")
	return allLines
}
